CoT(Chain of Thought) 기법 (참고자료)

아래는 요청하신 구조에 맞추어 Chain of Thought(이하 CoT) 기법에 대한 설명과, 사무직 회사원이 실제 업무에서 어떻게 활용하면 좋을지에 대한 예시를 정리한 내용입니다.

1. 개념

Chain of Thought(CoT) 기법이란, 대형 언어 모델에게 답변(결론)뿐만 아니라 그 결론에 이르는 중간 사고 과정까지 단계별로 드러내도록 유도하는 프롬프트 작성 방법입니다. 간단히 말해, 모델이 문제를 해결할 때 머릿속에서 ‘어떻게 사고’를 하고 있는지 그 과정을 단계별로 자세히 쓰도록 지시함으로써, 더 체계적이고 정확한 답변을 얻어내는 방법입니다.

주로 복잡한 수학 문제 풀이, 논리 퍼즐 해결, 전략적 분석 등이 필요한 상황에서 효과가 크게 나타납니다. CoT 프롬프트를 통해 모델에 ‘단계적 사고 과정(Reasoning Steps)’을 직접 요청하면, 모델이 응답 과정에서 스스로 논리를 점검하여 답변의 품질을 높이도록 유도할 수 있습니다.

2. 개념에 대한 예시

  • 예시 질문
     “다음 수학 문제를 단계별로 풀어줘. 2x+3=92x + 3 = 9. 계산 과정을 자세히 보여주고 최종 해답을 알려줘.”

  • CoT 방식 답변 예시(단순화 버전)

    먼저 식 2x+3=92x + 3 = 9에서 ‘+3’을 없애려면 양변에서 3을 뺀다.그러면 2x=62x = 6이 된다.이제 양변을 2로 나누면 x=3x = 3이라는 해를 얻는다.

위 예시처럼, 단순한 방정식에서도 ‘단계별 사고’를 명시적으로 보여주도록 프롬프트에서 요구함으로써 논리적이고 투명한 답변 과정을 이끌어낼 수 있습니다.

4. 회사원 사무직이 사용할 때 어떻게 사용하면 좋을지?

회사원 사무직 업무는 보고서 작성, 데이터 분석, 업무 절차 기획, 프로젝트 계획 수립 등과 같이 체계적인 논리 전개가 중요한 일이 많습니다. 이때 CoT 기법을 활용하면, 아래와 같은 이점이 있습니다.

  1. 보고서 초안 작성 시

    보고서의 핵심 내용을 단계별 논리로 정리하도록 모델에 요청하여, 초안을 빠르게 잡을 수 있습니다.예) “이 주제에 대해 각각의 문제점, 원인, 해결방안을 단계적으로 정리해줘”라고 명시하면 모델이 체계적인 내용 구성을 제안합니다.
  2. 의사결정 근거 제시

    새로운 프로젝트나 솔루션을 제안할 때, 모델이 각 단계별 이유와 근거를 설명하도록 유도하면 설득력 있는 기획 초안이 나옵니다.
  3. 단계별 업무 프로세스 구축

    업무를 여러 단계로 나누어 ‘어떤 단계에서 어떤 자료가 필요한지’, ‘누가 담당해야 하는지’, ‘어떤 산출물이 나오는지’ 등을 구조화할 수 있습니다.
  4. 논리적 사고 훈련

    팀원 간의 합의가 필요한 문서(예: 보고서, 기획서)를 작성할 때, CoT를 통해 모델이 제안한 논리적 근거를 확인하고 보강함으로써 문서의 완성도를 높일 수 있습니다.

5. 관련된 예시들

  1. 회의록 작성

    “오늘 회의에서 논의된 이슈들을 단계별로 정리하고, 각 이슈별로 해결책과 담당자, 마감일을 차례대로 제시해줘.”
  2. 규정/가이드라인 작성

    “우리 회사의 품질 관리 프로세스를 단계별로 나열하고, 각 단계에서 핵심적으로 확인해야 하는 사항을 체계적으로 정리해줘.”
  3. 비즈니스 제안서 초안

    “OOO 프로젝트 제안서를 작성할 때, 배경 → 목적 → 필요성 → 기대 효과 → 예산 및 일정 항목을 단계적으로 구성하고, 각 항목에서 고려해야 할 내용을 구체적으로 나열해줘.”

위 예시들은 모두 ‘단계별 사고 과정’을 요구하는 프롬프트를 작성함으로써, 모델이 응답을 구체적으로, 논리적으로 구성하도록 유도하는 사례입니다.

6. 사무에 사용되는 예시 (보고서 작성, 2025년 트렌드 보고서 작성)

  1. 보고서 작성 예시

    프롬프트 예시:
    “회사의 신제품 출시 전략 보고서를 작성하려고 하는데, 아래 순서로 단계별로 초안을 만들어줘:

    시장 조사 결과 정리경쟁사 분석우리 회사의 강점과 약점출시 시나리오(목표 고객, 마케팅 전략)예상 성과와 리스크 요인
    각 단계에서 주요 포인트와 참고 자료를 논리적으로 연결해줘.”CoT 활용 포인트:

    보고서 목차(단계)를 명확히 제시하고, 각 단계에서 어떤 내용을 다뤄야 하는지 구체적으로 질문.모델이 ‘단계별 사고 과정’을 적용해 내용을 자연스럽게 연결하도록 유도.
  2. 2025년 트렌드 보고서 작성 예시

    프롬프트 예시:
    “2025년 기술 및 소비자 트렌드를 분석하여 보고서를 작성해야 합니다.

    2025년 예상 기술 동향 (AI, 블록체인, 메타버스 등)소비자 행동 변화(온라인 시장 확대, 지속 가능성 이슈 등)기업들이 준비해야 할 전략 (기술 투자, 인프라 확충 등)
    각 항목을 단계적으로 분석하고, 예시 사례를 포함하여 제안서를 구성해줘.”CoT 활용 포인트:

    '1단계: 현재 시장 자료 수집 → 2단계: 핵심 기술별 성장 전망 → 3단계: 소비자 행동 변화 정리 → 4단계: 기업 전략 제시' 등으로 세분화하여, 각 단계를 구체적으로 써달라고 요구함.모델이 단계별로 사고를 펼쳐나가면서 구체적인 내용(예: 통계, 연구 보고서 레퍼런스 등)을 제시하도록 지시.

이처럼 CoT 기법을 사용하면, 보고서 작성 시에 구조적이고 심도 있는 자료를 얻을 수 있어, 업무 효율을 높이는 데 큰 도움이 됩니다.

마무리

  • CoT 기법 요약:

    모델에 중간 추론 과정을 공개적으로 드러내도록 요구.단계별 논리 전개를 구체적으로 지시해 고품질 응답을 유도.복잡한 보고서나 기획서, 분석 문서 작성 시 매우 유용.
  • 실무 활용 핵심:

    분야나 주제를 명확히 제시하고,단계적 접근(예: 1단계 → 2단계 → 3단계)을 지시하며,각 단계에서 다루어야 할 주요 요소를 구체적으로 써달라고 명령하면,보다 논리적이고 완성도 높은 문서를 빠르게 얻을 수 있습니다.

사무직 업무가 다양한 만큼, CoT 기법도 보고서·프로젝트 기획·의사결정 등 여러 방면에 적용할 수 있으니 필요에 맞게 변형해 사용해 보시기 바랍니다.

제로샷(Zero-Shot), 원샷(One-Shot), 퓨샷(Few-Shot) (참고자료)

아래는 제로샷(Zero-Shot), 원샷(One-Shot), 퓨샷(Few-Shot) 프롬프트 방식에 대해, 요청하신 구조에 맞추어 정리한 내용입니다.

1. 개념

(1) 제로샷(Zero-Shot)

  • 정의: 예시(샘플)를 전혀 주지 않고 모델에게 질문하거나 작업을 요청하는 방식
  • 특징:질의 시, 추가적인 맥락이나 예시가 없이도 모델이 스스로 학습된 지식을 바탕으로 답변간단한 요청이나 범용적인 질문에서 주로 활용

(2) 원샷(One-Shot)

  • 정의: 모델에게 주어진 요청과 함께 한 개의 예시(샘플)만 제공하는 방식
  • 특징:예시가 하나 주어지므로, 모델이 원하는 답변 형식이나 맥락을 부분적으로 인식제로샷보다 더 명확한 가이드 제공 가능

(3) 퓨샷(Few-Shot)

  • 정의: 모델에게 주어진 요청과 함께 여러 개(대부분 2~5개 정도)의 예시를 제공하는 방식
  • 특징:모델이 예시를 통해 맥락과 답변 양식을 더욱 확실히 파악제로샷이나 원샷에 비해 정확도가 높아질 가능성이 큼예시가 많아질수록 모델이 ‘학습’할 수 있는 정보가 많아져, 원하는 결과를 얻을 확률이 올라감

2. 개념에 대한 예시

(1) 제로샷 예시

  • 프롬프트:
    “2025년 전망 보고서를 작성해줘.”

  • 설명:

    별도의 샘플이나 예시 없이, 단순히 모델에게 ‘보고서’를 요청.모델은 내부적으로 학습된 지식만을 활용해 보고서 형식, 내용, 구조를 스스로 판단하여 작성.

(2) 원샷 예시

  • 프롬프트:
    “2025년 전망 보고서를 작성해줘. 예시는 다음과 같아:
    [예시]

    제목: 2030년 메타버스 시장 예측내용: ... (간단 요약)
    이러한 형식을 참고해서 작성해줘.”
  • 설명:

    예시가 한 개 주어짐.모델은 이 예시를 ‘참고’해 비슷한 형식으로 결과물을 제공.

(3) 퓨샷 예시

  • 프롬프트:
    “2025년 전망 보고서를 작성해줘. 예시는 다음과 같아:

    예시 A: 2030년 메타버스 시장 예측 보고서제목: 2030년 메타버스 시장내용: 시장 성장률, 주요 경쟁 업체, 핵심 기술 흐름 등예시 B: 2023년 소비자 트렌드 분석 보고서제목: 2023년 소비자 행동 분석내용: 온라인 구매 패턴, 영향력 있는 소셜 미디어 플랫폼, 개인화 서비스 등
    위 두 개 예시를 참고해, 2025년 트렌드를 분석하는 보고서를 작성해줘.”
  • 설명:

    예시가 여러 개(2개 이상) 주어짐.모델은 각각의 예시에서 공통되는 형식·요소를 파악해, 보다 일관성 있고 구체적인 보고서를 생성.

4. 회사원 사무직이 사용할 때 어떻게 사용하면 좋을지?

사무직 회사원은 문서 작성, 기획, 데이터 분석 등 다양한 업무를 수행합니다. 제로샷, 원샷, 퓨샷 방식을 적절히 선택해 활용하면, 다음과 같은 이점이 있습니다.

  1. 단순 질의 응답(제로샷)

    빠르게 참고 자료가 필요하거나, 간단한 지식 기반 질문을 할 때예: “OO 산업의 현재 시장 점유율이 어떻게 되는지 알려줘.”
  2. 템플릿 기반 보고서/문서 작성(원샷)

    회사에서 이미 쓰고 있는 표준 양식이 있거나, 간단한 예시 하나로 형식을 안내할 때예: “우리 회사 보고서 양식이 이건데, 이 양식에 맞춰서 내용 작성해줘.”
  3. 복잡하고 구체적인 문서 요구(퓨샷)

    다채로운 형식을 포함하거나, 섹션별 요구 사항이 많을 때예: “이전 두 개 보고서 스타일 + 추가 예시 하나를 참조해서 새로운 제안서를 작성해줘.”

이처럼 업무 상황에 따라,

  • 제로샷은 가장 빠르게 내용 초안을 얻을 때,
  • 원샷은 간단한 예시 기반의 문서 생성이 필요할 때,
  • 퓨샷은 여러 개의 예시를 참고해 정밀도 높은 문서를 만들 때 선택 가능합니다.

5. 관련된 예시들

  1. 인사 평가 문서 작성

    제로샷: “직원 인사 평가 양식을 만들어줘.” (샘플 없음 → 모델이 알아서 작성)원샷: “이런 형식의 인사 평가 문서가 있는데, 똑같이 만들어줘.” (단 하나의 샘플 제시)퓨샷: “작년에 사용한 인사 평가 양식 두 가지가 있으니 참고해서, 올해 평가에 맞춘 양식을 만들어줘.” (두 개 이상의 샘플 제시)
  2. 시장 조사 보고서 초안

    제로샷: “신제품 시장 조사를 위한 보고서 초안을 작성해줘.”원샷: “이 보고서 샘플처럼 작성해줘. (예시 1개 첨부)”퓨샷: “작년 보고서와 외부 컨설팅사의 보고서 등, 두 개 예시를 참고해 올해 시장 조사 보고서 초안을 만들어줘.”
  3. 홍보 자료(브로슈어) 기획

    제로샷: “OO 제품 홍보용 브로슈어를 만들어줘.”원샷: “이 브로슈어 샘플처럼 작성해줘.”퓨샷: “아래 두 가지 브로슈어 예시(소비재/산업재)를 참고해서 OO 제품 홍보 자료를 만들어줘.”

6. 사무에 사용되는 예시 (보고서 작성, 2025년 트렌드 보고서 작성)

  1. 보고서 작성

    제로샷 예시


     “다음 주 임원 보고 자료를 작성해줘. 주제는 ‘우리 회사의 하반기 목표 달성 계획’이야.”


    간략한 맥락만 제공하면, 모델이 자체적으로 내용을 구성해 초안을 만들어줌.원샷 예시


     “이전 임원 보고 자료 샘플(아래 첨부)을 참고해서, 이번에도 비슷한 형식으로 작성해줘.”


    샘플이 하나 있다면, 이전 자료의 형식·흐름을 따라가도록 모델에 지시.퓨샷 예시


     “작년 3분기 보고서와 이번 1분기 보고서 샘플을 참고해서, 올해 하반기 목표 달성 계획 보고서를 종합적으로 작성해줘.”


    샘플을 여러 개 제공하여, 두 자료의 장점을 결합한 보고서를 생성.
  2. 2025년 트렌드 보고서 작성

    제로샷 예시

     “2025년 산업 트렌드와 소비자 동향을 분석하는 보고서를 작성해줘.”


    원샷 예시

     “이러한 목차(기술 트렌드, 시장 규모, 주요 기업 동향, 예상 리스크)로 정리된 보고서를 참고해, 2025년 전망 보고서를 같은 형식으로 작성해줘.”


    퓨샷 예시

     “① 2023년 기술 트렌드 보고서, ② 2024년 소비자 동향 보고서를 예시로 줄 테니, 두 가지를 조합해 2025년 산업 & 소비자 트렌드 보고서를 작성해줘.”


마무리

  • 제로샷은 간단·범용 질문에 빠르게 답변을 얻을 때 유용.
  • 원샷은 단일 예시를 통해 모델에게 형식·내용의 힌트를 줄 때 효과적.
  • 퓨샷은 여러 예시를 통해 보다 높은 정확도와 일관성을 추구할 때 활용.

실제 사무 환경에서는 작성해야 할 문서나 자료의 종류가 다양합니다.

  • 문서 양식 하나(원샷) 만으로도 회사 표준을 쉽게 반영 가능.
  • 여러 양식을 섞어 새로운 형태를 만들고 싶다면 퓨샷을 적용.
  • 빠른 초안이 필요하거나 샘플 없이 아이디어만 얻고 싶다면 제로샷을 시도해볼 수 있습니다.

상황과 목적에 맞춰 제로샷, 원샷, 퓨샷을 적절히 선택해 활용해 보세요!

후카츠식 프롬프트 작성법 (참고자료)

아래는 후카츠식 프롬프트 작성법을 요청하신 구조에 맞추어 정리한 내용입니다.

1. 개념

후카츠식 프롬프트 작성법은 AI(특히 대형 언어 모델, LLM)에게 지시를 내릴 때, 단순 질의응답 형태를 넘어 ‘역할(Role), 목적, 조건, 단계, 형식’ 등을 구체적으로 구조화하여 명확히 전달하는 기법입니다. 이를 통해 모델이 혼선 없이 작업을 이해하고, 정확하고 일관된 답변을 생성하도록 돕습니다.

주요 특징

  1. 명확한 역할 정의

    모델이 마치 특정 직무나 전문가인 것처럼, 미리 구체적인 역할을 부여함. (예: “당신은 분석가입니다”)
  2. 단계별/항목별 지시

    1단계, 2단계 식으로 단계화하거나, 필요한 항목을 나열하여 모델의 답변 구조를 짜임새 있게 유도.
  3. 제한사항/조건 구체화

    글의 분량(예: A4 1장 이내), 형식(표, 리스트, 문단), 톤(격식, 전문성), 참고해야 할 키워드 등 조건을 명시.
  4. 출력 형식 지정

    모델이 답변을 어떤 형식(예: 제목-본문, 표, 개조식 등)으로 표현해야 하는지 구체적으로 안내.

이처럼 후카츠식 접근은 모델에게 ‘무엇을, 어떻게, 왜, 어느 정도까지’ 수행해야 하는지 분명하게 전달한다는 점에서, 일반적인 간단 질의보다 높은 품질의 결과물을 얻는 데 용이합니다.

2. 개념에 대한 예시

예시 상황: **‘신제품 출시 전략 보고서를 작성해 달라’**고 요청하는 경우

일반(단순) 프롬프트

“신제품 출시 전략 보고서를 작성해줘.”

  • 단점:모델이 자유롭게 작성하기 때문에, 문서 형식·길이·중점 사항 등이 제각각일 수 있음.핵심을 놓칠 수도 있고, 불필요하게 길어질 수도 있음.

후카츠식 프롬프트

역할: 당신은 글로벌 비즈니스 컨설턴트입니다.
목적: 우리 회사의 신제품 출시 전략 보고서를 작성해야 합니다.
조건:

  • A4 한 장 분량(약 500~600자 이내)시장 분석, 2) 경쟁사 전략, 3) 마케팅 방안, 4) 리스크 및 대응 방안 순으로 제시
  • 각 항목별로 표나 개조식 활용
    출력 형식:
  • 제목: “신제품 출시 전략 보고서”
  • 문서를 4개 섹션으로 나누고, 마지막에 요약(3줄 이내)을 추가
  • 장점:모델이 정확한 형식(제목, 섹션 구성, 요약)을 지키면서 답변분량(A4 한 장 분량)을 준수하고, 주요 항목(시장 분석, 경쟁사 전략 등)을 빠짐없이 다룸결과물이 일관성 있고 간결하며, 실제 보고서 형태에 가깝게 작성됨

4. 회사원 사무직이 사용할 때 어떻게 사용하면 좋을지?

사무직 회사원은 보고서 작성, 분석 자료 정리, 회의록 작성, 기획 업무 등에서 후카츠식 프롬프트를 적극 활용할 수 있습니다. 구체적으로는 다음과 같은 이점이 있습니다.

  1. 문서 작성 정확도 향상

    필요 항목(제목, 목차, 각 섹션, 요약 등)을 단계별로 지시함으로써 누락 없이 문서를 완성.
  2. 보고서·기획서 작성 속도 개선

    모델이 구체적인 형식에 맞춰 한 번에 초안을 제시하므로, 수정과 피드백에 드는 시간이 단축됨.
  3. 협업 시 업무 효율 증대

    팀원 간에 표준화된 프롬프트 양식을 공유하면, 일관된 보고서나 문서 양식을 유지 가능.초안을 얻은 뒤, 실제 담당자가 추가 보완·수정하는 방식으로 업무 프로세스가 빨라짐.
  4. 프롬프트 반복 활용 가능

    동일 혹은 유사한 유형의 보고서를 지속적으로 작성해야 할 때, 후카츠식 프롬프트 템플릿을 만들어두면 재사용이 용이.

5. 관련된 예시들

  1. 프로젝트 제안서 작성

    후카츠식 요소:역할: “당신은 전문 컨설턴트입니다.”조건: “가용 예산, 인력, 기간을 표로 정리. 최대 2페이지. 전문 용어는 최소화.”단계: “1단계-프로젝트 개요, 2단계-비용·일정, 3단계-주요 리스크 및 대응 방안”출력 형식: “문서 마지막에 요약(5줄 이내)을 써줘.”
  2. 시장 조사 보고서

    후카츠식 요소:역할: “당신은 시장 조사 전문가입니다.”조건: “가장 최근(2024~2025년) 트렌드 중심, 주요 경쟁 업체 3곳 분석, 표와 그래프 서술.”단계: “1단계-시장 개요, 2단계-경쟁사 분석, 3단계-결론 및 시사점”출력 형식: “섹션마다 소제목을 붙이고, 마지막에 3줄 요약.”
  3. 인사 평가 지침서

    후카츠식 요소:역할: “당신은 HR 전문가입니다.”조건: “올해 새로 도입된 평가 기준과 과거 기준 비교, 이해하기 쉬운 예시 포함.”단계: “1단계-평가 항목 소개, 2단계-기존과 변경점 비교, 3단계-실무 적용 시뮬레이션”출력 형식: “표를 사용해 변경점 요약, 2페이지 이내.”

이처럼 **‘역할, 조건, 단계, 형식’**의 네 가지를 명확히 구성하는 것만으로도 업무에 특화된 문서를 손쉽게 생성할 수 있습니다.

6. 사무에 사용되는 예시 (보고서 작성, 2025년 트렌드 보고서 작성)

  1. 보고서 작성 예시

    후카츠식 프롬프트


     “당신은 사업기획 전문가입니다. 이번 주 임원 보고서를 작성해줘.
    조건: A4 1장 분량, 숫자 데이터는 표로 정리, 핵심 이슈를 3가지로 구분.
    단계: 1단계-상반기 실적 요약, 2단계-중점 과제(3개), 3단계-리스크 및 해결 방안.
    출력 형식: 맨 마지막에 ‘이번 주 임원 보고서 요약(3줄 이내)’ 섹션을 넣어줘.”


    장점:

    체계적인 보고서 초안 생성수정·보완 작업 시 누락 최소화
  2. 2025년 트렌드 보고서 작성 예시

    후카츠식 프롬프트


     “당신은 미래학자이자 트렌드 분석가입니다. 2025년 기술 및 소비자 동향을 중심으로 보고서를 작성해줘.
    조건: IT 분야(인공지능, 메타버스, IoT)와 소비자 행동(온라인 구매 습관, 지속 가능성 이슈)에 대한 최신 전망 포함. 2장 분량 제한.
    단계: 1단계-주요 기술 동향, 2단계-소비자 행동 변화, 3단계-기업 대응 전략.
    출력 형식: 각 단계별로 소제목을 달고, 표와 개조식 목록을 활용하여 요점을 간결히 정리. 마지막에 요약 3줄 첨부.”


    장점:

    여러 섹션(기술·소비자·기업 전략)을 구체적으로 지시출력 분량 제한 & 형식 지정으로, 불필요하게 길어지는 답변 방지

마무리

  • 후카츠식 프롬프트 작성법 요약

    역할(Role): 모델이 어떤 전문가/캐릭터로서 답변해야 하는지 명확히 설정목적/조건: 글의 분량, 작성 톤, 사용해야 할 키워드, 금지 항목 등을 구체화단계(Structure): 작업을 여러 단계로 나누어 순차적으로 안내출력 형식(Format): 표, 리스트, 문단, 요약 등 최종 결과물의 형태를 지정
  • 업무 활용 핵심:

    사무직에서 필요한 보고서, 제안서, 회의록, 기획 문서 등에서 후카츠식 기법을 적용하면, 빠르고 일관성 있는 초안을 생성하고 추가 수정도 쉬워집니다.반복되는 문서 작성에 공통 템플릿을 두고, 후카츠식 요소만 잘 세팅해 두면 생산성이 크게 향상됩니다.

이처럼 후카츠식 접근은 간단한 질의응답을 넘어, AI에게 구체적이면서도 단계적인 지시를 내려 더욱 정확도 높은 결과를 얻고 싶을 때 탁월한 방법입니다. 회사 업무 뿐 아니라 다양한 분야(교육, 마케팅, 컨설팅 등)에서도 응용해 보시기를 권장드립니다.

프롬프트 엔지니어링 전략으로 결과를 향상시키기 : 이 가이드는 대규모 언어 모델(때로는 GPT 모델로 불리기도 함, 예: GPT-4)에서 더 나은 결과를 얻기 위한 전략과 전술을 공유합니다. 여기서 설명된 방법들은 때로는 결합하여 더 큰 효과를 발휘할 수도 있습니다. 어떤 방법이 여러분에게 가장 잘 맞는지 실험해보는 것을 권장합니다.  또한, GPT 모델의 가능성을 보여주는 예제 프롬프트를 탐색할 수도 있습니다.

더 나은 결과를 얻기 위한 6가지 전략

1. 명확한 지시 작성

모델은 여러분의 의도를 읽을 수 없습니다. 출력물이 너무 길면 간결하게 요청하고, 출력물이 너무 단순하면 전문적인 수준의 글쓰기를 요청하세요. 형식이 마음에 들지 않으면 원하는 형식을 보여주세요. 모델이 여러분의 의도를 추측하지 않도록 하면 원하는 결과를 얻을 가능성이 높아집니다.

전술:

  • 쿼리에 세부 정보를 포함하여 더 관련성 높은 답변 얻기일반 예: "엑셀에서 데이터를 합산하는 방법을 알려줘" 대신, "엑셀에서 열의 금액을 합산해 오른쪽 열에 '합계'라는 제목으로 자동 계산되도록 설정하는 방법을 알려줘."실무 예: "2025년 디지털 트렌드 보고서 작성 시, AI가 이끄는 자동화 기술의 성장세에 대해 구체적인 데이터와 주요 사례를 포함해주세요."
  • 모델에게 특정 페르소나를 채택하도록 요청일반 예: "당신은 역사 전문가입니다. 고대 그리스의 민주주의 제도에 대해 설명해주세요."실무 예: "당신은 트렌드 분석 전문가입니다. 2025년 디지털 마케팅 트렌드 중, '맞춤형 광고 기술의 진화'에 대해 전문가 수준으로 설명해주세요."
  • 입력의 구분된 부분을 명확히 표시하기 위해 구분자 사용일반 예:"""  이 텍스트를 요약해 삼행시 형식으로 작성해주세요. 
    """  실무 예:"""  2025년 보고서용 주요 트렌드:
    1. AI 기반 자동화
    2. AR/VR의 대중화
    3. 클라우드 네이티브 기술 확산
    이를 기반으로 각 트렌드의 요약을 작성해주세요. 
    """
  • 작업 완료에 필요한 단계 지정일반 예: "문서에서 요점을 요약한 뒤, 이를 기반으로 한 질문 3개를 작성해주세요."실무 예: "2025년 디지털 기술 트렌드 보고서를 작성하기 위해 다음 단계를 따라주세요.기술별 정의 작성성장 데이터를 요약관련 기업 및 사례 분석 추가"
  • 예제 제공일반 예: "다음과 같은 형식으로 답변해주세요: '1. 요점 A, 2. 요점 B'"실무 예: "다음 형식에 따라 2025년 디지털 트렌드 보고서의 AI 트렌드 섹션을 작성해주세요.트렌드 제목주요 내용 요약 (100자)데이터 예시 (성장률, 기업 사례)"
  • 출력물의 원하는 길이 명시일반 예: "50자 이내로 답변해주세요." 또는 "3개의 주요 포인트로 요약해주세요."실무 예: "2025년 기술 트렌드 요약을 3개의 간결한 문장으로 작성해주세요. 각 문장은 20자 이내로 제한해주세요."

2. 참조 텍스트 제공

언어 모델은 특히 난해한 주제나 인용, URL 요청 시 허구의 답을 만들어내기 쉽습니다. 학생이 시험에서 참고 자료를 사용하면 더 나은 성과를 거둘 수 있듯이, 참조 텍스트를 제공하면 모델이 허구를 줄이고 답변의 정확성을 높일 수 있습니다.

전술:

  • 참조 텍스트를 사용하여 답변하도록 모델 지시일반 예: "아래 텍스트를 참조하여 질문에 답변하세요.텍스트: ‘지구 온난화는 주로 인간 활동으로 인한 온실가스 배출 증가 때문이다.’  질문: 지구 온난화의 주요 원인은 무엇인가요?"실무 예: "다음은 '2024년 AI 기술 보고서'의 일부입니다. 이를 참조하여 '2025년 AI 자동화의 방향성'을 예측해 작성해주세요.텍스트: '2024년, AI는 데이터 처리와 의사결정 자동화에서 30% 성장률을 기록하며 기업 혁신을 이끌었다.'  ```"
  • 참조 텍스트에서 인용과 함께 답변하도록 모델 지시일반 예: "다음 텍스트를 기반으로 답변을 작성하고, 텍스트에서 인용한 부분을 명시하세요."실무 예: "다음은 '2025년 클라우드 기술 보고서'의 일부입니다. 이를 인용해 클라우드 기술이 다른 산업에 미치는 영향을 설명해주세요.텍스트: '클라우드 네이티브 애플리케이션은 IT 비용 절감과 개발 속도 증가에 핵심 역할을 했다.'  ```"

3. 복잡한 작업을 더 간단한 하위 작업으로 나누기

소프트웨어 엔지니어링에서 복잡한 시스템을 모듈 구성 요소로 분해하는 것이 좋은 관행인 것처럼, 언어 모델에 제출하는 작업에서도 동일합니다. 복잡한 작업은 단순한 작업보다 오류율이 높습니다. 따라서 복잡한 작업은 간단한 작업의 워크플로우로 재정의되어야 합니다.

전술:

  • 사용자 쿼리에 대한 가장 관련성 높은 지침 식별을 위해 의도 분류 사용일반 예: 고객 서비스 요청을 분류하기 위해 "이 요청은 청구서 관련인가요, 기술 지원인가요, 계정 관리 관련인가요?"라고 질문합니다.실무 예: "2025년 디지털 기술 보고서 섹션을 작성하기 위해, 기술별 섹션을 'AI', '클라우드', 'IoT'로 나누고 각 섹션별 주요 트렌드를 요약해주세요."
  • 긴 대화가 필요한 응용 프로그램의 경우 이전 대화를 요약하거나 필터링일반 예: "지금까지 대화 내용을 요약한 뒤, 핵심 논점을 도출해주세요."실무 예: "지난 보고서 초안에 언급된 기술 트렌드를 요약한 뒤, 추가적으로 필요한 항목을 제안해주세요."
  • 긴 문서를 부분적으로 요약하고 전체 요약을 재귀적으로 구성일반 예: "다음과 같은 단계로 문서를 요약하세요.각 섹션을 요약합니다.요약된 섹션들을 결합하여 전체 문서의 요약을 만듭니다."실무 예: "2025년 보고서를 작성하기 위해, 각 기술별 데이터 요약(예: AI, 클라우드, IoT)을 제공하고, 이를 통합하여 전체 보고서를 구성해주세요."

4. 모델에게 "생각할 시간" 주기

17 곱하기 28을 곱하라고 하면 즉시 답을 알지 못할 수 있지만 시간을 들이면 답을 계산할 수 있습니다. 마찬가지로 모델도 즉각적으로 답하려고 할 때보다 시간을 들여 답을 계산할 때 추론 오류가 줄어듭니다. 답변 전에 "사고의 과정"을 요청하면 모델이 보다 신뢰할 수 있는 답을 도출할 가능성이 높아집니다.

전술:

  • 결론에 성급히 도달하지 않고 스스로 해결책을 찾도록 모델 지시일반 예: "문제를 단계별로 해결한 후 답변을 작성해주세요."실무 예: "2025년 AI 기술 트렌드의 경제적 영향을 분석하기 위해, 다음과 같은 사고 과정을 따르세요:기술 성장 데이터를 수집합니다.주요 기업의 사례를 조사합니다.이를 기반으로 경제적 파급 효과를 분석합니다."
  • 내적 독백 또는 일련의 쿼리를 사용하여 모델의 추론 과정 숨기기일반 예: "모든 과정을 숨기고, 최종 답변만 출력하세요."실무 예: "보고서의 각 기술 섹션을 작성하되, 중간 추론 단계는 숨기고 최종 문장만 출력하세요."
  • 모델이 이전 단계에서 놓친 부분이 있는지 확인 요청일반 예: "이전에 답변하지 않은 부분이 있는지 확인하고 추가 답변을 제공해주세요."실무 예: "이전 초안에서 누락된 'IoT 기술' 관련 트렌드를 다시 확인하고 내용을 보충해주세요."

5. 외부 도구 사용

모델의 약점을 보완하기 위해 다른 도구의 출력을 모델에 제공하세요. 예를 들어, 텍스트 검색 시스템(RAG 또는 검색 증강 생성이라고 함)은 관련 문서를 모델에 전달할 수 있습니다. OpenAI의 코드 인터프리터 같은 코드 실행 엔진은 수학 계산 및 코드 실행을 도울 수 있습니다.

전술:

  • 효율적인 지식 검색 구현을 위해 임베딩 기반 검색 사용일반 예: "문서 내에서 관련 내용을 검색하여 질문에 답변하세요."실무 예: "2025년 디지털 트렌드 보고서 작성 시, 주요 AI 관련 데이터를 데이터베이스에서 검색해 보고서에 반영해주세요."
  • 정확한 계산을 수행하거나 외부 API를 호출하기 위해 코드 실행 사용일반 예: "다음 방정식의 해를 찾기 위해 코드를 작성하고 실행하세요."실무 예: "2025년 기술 트렌드 시장 점유율 분석을 위해, Python 코드를 작성하고 계산 결과를 보고서에 삽입해주세요."
  • 특정 기능에 대한 접근 권한 모델에 제공일반 예: "이 API를 사용하여 데이터를 검색하고 결과를 표시하세요."실무 예: "API를 사용해 2025년 최신 기술 투자 데이터를 가져오고, 이를 보고서에 추가하세요."

6. 변경 사항을 체계적으로 테스트

성능을 개선하는 것은 성능을 측정할 수 있을 때 더 쉽습니다.

전술:

  • 모범 답안과 비교하여 모델 출력을 평가일반 예: "아래 답변이 다음 기준을 충족하는지 확인하세요.
    주요 사실 포함 여부 /  논리적 모순 없음"실무 예: "2025년 보고서 초안을 검토하며, 다음 기준을 확인하세요:
    모든 기술 트렌드가 포함되었는지 / 주요 데이터를 정확히 반영했는지"

가독성

헤더, 리스트, 테이블 등으로 구조화되어 가독성이 높음

단순 텍스트가 길게 이어질 경우 가독성이 떨어질 수 있음

강조 표현

**볼드**, *이탤릭*, ==하이라이트==로 직관적 강조 가능

강조가 제한적이어서 대문자, 이모지 등에 의존해야 함

코드 표현

``` (트리플 백틱)으로 코드 블록 구분이 가능해 소스 코드를 명확히 표시할 수 있음

코드와 일반 텍스트가 섞여 구분이 어렵고, 가독성이 크게 떨어질 수 있음

링크·이미지 삽입

[텍스트](URL) 및 ![이미지](URL)로 시각적 구분이 쉬움

URL만 나열해야 하며, 설명이 부족하거나 이미지가 제대로 표현되지 않을 수 있음

정보 구조화

제목(헤더), 리스트, 수평선 등을 통해 체계적으로 정보 전달 가능

구분선이 없어 한 문단에 정보가 몰려 정리되어 보이지 않을 수 있음

ChatGPT 이해도

구조와 키워드가 명확하여 맥락 파악이 빠르고, 복잡한 내용도 더 쉽게 이해
```

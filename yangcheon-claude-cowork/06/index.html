클로드 데스크톱 심화 8회차 나만의 블로그 사이트

STEP 0

오늘의 지도

옵시디언에서 쓴 메모가 인터넷에 내 블로그로 뜹니다. 오늘은 그 길을 처음부터 끝까지 한 번 걸어 봅니다.

0-1

세 친구 한눈에 보기

쉽게 말하면공책에 쓰고, 금고에 넣으면, 전광판이 알아서 바꿔 줍니다.

진짜 이름쉽게 말하면하는 일
옵시디언공책글(md)을 쓰고 고치는 곳. 내 컴퓨터 안에 있어요.
깃허브금고글을 넣어 두는 인터넷 보관함. 고친 기록이 다 남아서 되돌릴 수 있어요.
버셀전광판금고를 지켜보다가 글이 들어오면 블로그를 다시 띄워요.
0-2

md는 원고, 블로그는 출판본

쉽게 말하면우리는 원고(md)만 씁니다. 예쁜 블로그 모양(껍데기)은 미리 만들어 둔 틀이 입혀 줍니다.

  • md: 옵시디언에서 쓰는 글. 여러분이 만지는 건 이것뿐
  • 틀(껍데기): 블로그 디자인과 "최신 글이 맨 위" 규칙. 이미 준비돼 있어요
  • 버셀: 둘을 합쳐 인터넷에 띄워요
그래서 좋은 점디자인이 매번 똑같이 깔끔하고, 새 글은 날짜를 보고 자동으로 맨 위에 와요.
0-3

시작 루틴

쉽게 말하면이 컴퓨터는 다른 반도 씁니다. 시작할 때 내 계정, 끝날 때 로그아웃.

  1. 클로드 앱에서 로그아웃 → 내 계정으로 로그인
  2. USB 꽂기 (없으면 오늘은 D: 드라이브)
  3. 휴대폰을 옆에 두기 — 오늘 인증번호가 메일·문자로 와요

내 이름으로 클로드가 열려 있으면 준비 끝

STEP 1

새 공책 만들기

지난 시간에 배운 옵시디언·웹 클리퍼·CLAUDE.md를 새 폴더로 한 번 더 합니다. 깨끗한 공책에서 시작하면 헷갈리지 않아요.

1-0

왜 폴더를 나눌까 — 부엌으로 생각하기

쉽게 말하면장바구니 → 냉장고 칸 → 요리 → 식탁. 칸이 나뉘어 있어야 섞이지 않아요.

부엌폴더왜 따로 둘까
장바구니inbox긁어 온 남의 기사를 원본 그대로 둬요. "이 말 어디서 봤지?" 할 때 출처 증거가 돼요.
냉장고 칸inbox/AI 등주제별 칸에 넣으면 꺼내 쓰기 쉬워요. "AI 칸에서 글 써 줘"처럼 시킬 수 있고, 칸 이름이 블로그 태그가 돼요.
요리posts재료로 만든 내 글. 남의 글과 섞이면 실수로 남의 기사를 올리게 돼요.
식탁블로그posts만 손님상에 나가요. 올리는 폴더가 딱 하나라 헷갈릴 일이 없어요.
클로드에게도 좋아요"정리는 inbox에서만, 글은 posts에만." 폴더가 곧 클로드의 업무 구역이 됩니다. 구역을 정해 주면 엉뚱한 파일을 건드리지 않아요.
blognote/ ← 새 공책 (옵시디언 보관함 = 클로드 프로젝트 폴더) ├─ CLAUDE.md ← 클로드가 제일 먼저 읽는 규칙 ├─ inbox/ ← 장바구니: 긁어 온 기사 │ ├─ AI/ ← 냉장고 칸 ("정리"하면 생겨요) │ └─ 경제/ └─ posts/ ← 요리: 내 블로그 글 (이것만 인터넷에)
1-1

새 폴더 만들기

쉽게 말하면새 공책을 꺼내고 장바구니와 요리 칸을 만듭니다.

  1. USB(없으면 D:)에서 마우스 오른쪽 → 새로 만들기 → 폴더 → 이름 blognote
  2. blognote 안에 폴더 두 개: inbox, posts

blognote 안에 inbox, posts가 보이면 성공

이름은 영어로, 띄어쓰기 없이한글이나 띄어쓰기는 프로그램마다 가끔 말썽을 부려요. 지난주 scrap 폴더는 그대로 두세요.
1-2

옵시디언에서 blognote 열기

쉽게 말하면옵시디언에게 "이제 이 공책을 쓸게" 하고 알려 줍니다.

  1. 옵시디언 왼쪽 아래 보관함 이름 클릭 → 보관함 관리하기... (처음 켠 분은 첫 화면이 바로 나와요)
  2. 버튼 세 개 중 보관함 폴더 열기 → blognote 선택 → 폴더 선택
"새 보관함 생성"은 누르지 않아요폴더는 1-1에서 이미 만들었어요. 이걸 누르면 엉뚱한 공책이 하나 더 생겨요.

왼쪽에 inbox, posts가 보이고 왼쪽 아래 이름이 blognote면 성공

1-3

웹 클리퍼를 새 공책에 연결

쉽게 말하면기사를 긁으면 장바구니(inbox)로 들어가게 주소를 적어 줍니다.

  1. 크롬 오른쪽 위 옵시디언 웹 클리퍼 아이콘 → 톱니바퀴(설정)
  2. 왼쪽 템플릿 아래 기본 템플릿 클릭
  3. 노트 칸이 Clippings면 지우고 inbox (지난주에 바꾼 분은 그대로)
  4. 같은 화면 보관소 칸이 비어 있으면 그대로, scrap이면 지우기
딱 다섯 글자만inbox 앞뒤에 빗금(/)이나 폴더 이름을 붙이지 않아요.
웹 클리퍼는 보관함을 "보관소"라고 불러요. 같은 말이에요.
1-4

클로드 프로젝트 「블로그 공책」 만들기

쉽게 말하면클로드에게 "오늘은 이 공책만 보고 일해" 하고 책상을 정해 줍니다.

  1. 클로드 앱 왼쪽 프로젝트 → + → 기존 폴더 사용 → blognote 선택
  2. 이름 블로그 공책 → 만들기 → 폴더 접근 창이 뜨면 허용
  3. 프로젝트 안 새 대화에 지금 연결된 폴더에 뭐가 있어?

클로드가 inbox, posts가 있다고 답하면 성공

오늘은 전부 「블로그 공책」에서지난주 「내 스크랩북」에서 하면 다른 공책에 써져요.
1-5

규칙 파일(CLAUDE.md) 만들기

쉽게 말하면클로드가 출근하면 제일 먼저 읽는 "우리 집 규칙"을 붙여 둡니다. 이번엔 업무 구역까지 적어요.

「블로그 공책」 새 대화에 붙여 넣기
[상황] 나는 관심 기사를 웹 클리퍼로 blognote/inbox 폴더에 모은다. 이 기사로 내 블로그 글을 쓸 거다.
[요청] blognote 폴더 맨 위에 CLAUDE.md 파일을 만들어 줘. 내용은 아래 규칙.
[폴더 구역]
- inbox: 남의 기사 원본. 내용을 고치거나 지우지 않는다.
- posts: 내 블로그 글만 둔다.
[규칙]
- 내가 "정리"라고 하면: inbox 폴더 바로 아래에 새로 들어온 파일만 대상으로, 주제를 보고 inbox 안의 주제 폴더(예: inbox/AI, inbox/경제)로 옮긴다. 주제 폴더는 5개를 넘지 않게 하고 이름은 띄어쓰기 없이 짓고, 이미 주제 폴더에 들어간 파일은 건드리지 않는다. 다 하면 무엇을 어디로 옮겼는지 한 줄씩 보여 준다.
- 날짜와 시간은 한국 시간 기준.
- 파일을 지우기 전에는 반드시 나에게 묻는다.

옵시디언 왼쪽에 CLAUDE.md가 생기면 성공

"새로 들어온 파일만"이 핵심이 말이 있어서 정리를 여러 번 해도 이미 정리한 기사가 다시 섞이지 않아요.
1-6

기사 긁어 오기 → "정리" 한 단어

쉽게 말하면장바구니에 재료를 담고, 한 마디로 냉장고 칸에 나눠 넣어요.

  1. 구글 뉴스에서 관심 기사 1~2개를 하나씩 열고 웹 클리퍼 → Obsidian에 추가하기
  2. 처음 한 번은 크롬이 "Obsidian을 여시겠습니까?" 물어요 → 항상 허용 체크 → 열기
  3. 「블로그 공책」 새 대화 → 정리

클로드가 되묻지 않고 inbox 안에 주제 폴더를 만들어 기사를 옮기면 성공

기사가 Clippings 폴더로 갔다면1-3을 다시 확인하고, 들어간 기사는 옵시디언에서 inbox로 끌어 옮기면 돼요.
한 걸음 더기사 하나 더 긁고 정리를 또 해 보세요. 정리된 건 그대로, 새 기사만 칸에 들어가요.
STEP 2

금고와 전광판 회원가입

깃허브(금고)와 버셀(전광판)에 가입합니다. 숫자를 넣으라는 화면이 몇 번 나오니 휴대폰과 메일함을 옆에 두세요.

2-1

숫자(인증번호)를 넣는 순간

쉽게 말하면"진짜 본인 맞아요?" 하고 묻는 거예요. 숫자는 전부 내 메일이나 내 휴대폰으로 와요.

언제무엇이어디로
깃허브 가입 마지막숫자 코드가입한 이메일
교육장 컴퓨터에서 깃허브에 로그인할 때기기 인증 코드 (처음 보는 컴퓨터라서 물어요)깃허브 이메일
버셀을 이메일로 가입할 때6자리 코드이메일
버셀 가입 중 (일부 사람만)문자 인증번호휴대폰
버셀에 저장소 권한을 줄 때비밀번호를 한 번 더 물을 수 있어요깃허브 비밀번호
숫자와 비밀번호는 내 손으로만옆 사람이나 강사에게 불러 주지 않아요. 메일이 안 오면 스팸함을 보고 1분 기다려요.
2-2

깃허브(금고) 가입

  1. github.com → Sign up (구글 계정이 있으면 Continue with Google이 빨라요)
  2. 이메일 → 비밀번호 → 아이디 (영어로 쉽게. 블로그 주소에 쓰일 수 있어요)
  3. 사람인지 확인하는 퍼즐이 나오면 풀기
  4. 이메일로 온 숫자 입력
  5. 질문(팀 규모 등)은 Skip 또는 아무거나

깃허브 첫 화면(Dashboard)이 보이면 성공

2단계 인증은 집에서 천천히 켜도 돼요.
2-3

버셀(전광판) 가입

  1. vercel.com → Sign Up
  2. 요금제는 Hobby(무료, 개인용) → 이름 입력
  3. Continue with GitHub 선택 → 깃허브가 물으면 Authorize
  4. 휴대폰 문자 인증이 나오면 번호 입력 (안 나오는 사람도 있어요)

버셀 대시보드가 보이면 성공

깃허브로 가입하는 이유금고와 전광판이 처음부터 연결돼서 나중이 편해요.
깃허브 가입에서 막혔다면버셀만 이메일로 가입하고 계속 따라오세요. STEP 5-3 "버셀로 바로 올리기"로 갑니다.
STEP 3

내 글 쓰기

장바구니의 기사로 클로드가 초안을 쓰고, 마무리 한 줄은 내가 씁니다. 그 한 줄이 있어야 내 블로그예요.

3-1

"글쓰기" 규칙 추가하기

쉽게 말하면"글쓰기"라고만 하면 같은 모양으로 글이 나오게 레시피를 적어 둡니다. 규칙을 설계하는 일이라 똑똑한 모델(Opus)이 좋아요.

「블로그 공책」 새 대화 · 모델 Opus (안 보이면 기본)
[상황] blognote 폴더의 inbox(주제 폴더 포함)에 웹 클리퍼로 모은 기사가 있다. 이 글들로 내 블로그를 만들 거다.
[목적] 남의 기사 본문을 그대로 옮기지 않고, 내 말로 쓴 짧은 글만 블로그에 올리고 싶다.
[요청] CLAUDE.md 맨 아래에 아래 "글쓰기" 규칙을 추가해 줘. 기존 내용은 지우지 마.
[글쓰기 규칙]
- 내가 "글쓰기"라고 하면: posts 글들의 source 주소와 겹치지 않는 inbox 기사(주제 폴더 안 포함) 1개를 골라 posts 폴더에 md 글 1개를 만든다.
- 파일 이름: 날짜 + 짧은 제목 (예: 2026-10-19 노벨상 기사.md)
- 맨 위 머리말은 반드시 이 모양:
  ---
  title: 글 제목
  date: 지금 한국 시각(YYYY-MM-DD HH:mm, 예: 2026-10-19 19:40) — 시각은 컴퓨터에서 확인해서 적는다
  tags: [그 기사가 들어 있던 주제 폴더 이름]
  summary: 목록에 보일 한 줄 소개
  source: 원문 주소
  ---
- 본문은 "## 한 줄 요약", "## 내 생각" 두 칸. 요약은 3줄 이내 내 말로. 내 생각 칸은 비워 두고 "(여기에 내 생각 한 줄)"이라고만 적는다.
- 기사 문장을 길게 그대로 옮기지 않는다. 기사 사진·그림(![…])은 넣지 않는다.
- title·summary에 콜론(:)이 들어가면 값 전체를 큰따옴표로 감싼다.

CLAUDE.md 맨 아래에 "글쓰기" 규칙이 붙으면 성공

날짜에 시각까지 적는 이유같은 날 두 편을 써도 나중에 쓴 글이 맨 위로 오게 하려고요.
3-2

"글쓰기" 한 단어

쉽게 말하면레시피가 있으니 주문은 한 단어면 돼요. 정해진 일이라 가벼운 모델(Sonnet)로 충분해요.

  1. 「블로그 공책」 새 대화 → 글쓰기

posts 폴더에 md 글 1개가 생기면 성공

클로드가 되물으면CLAUDE.md 열어서 글쓰기 규칙 있는지 보여줘 → 없으면 3-1을 다시.
3-3

옵시디언에서 내 생각 한 줄

쉽게 말하면AI는 초안, 마무리는 내 손. 이 한 줄이 블로그의 주인이 누군지 말해 줘요.

  1. 옵시디언 posts 폴더 → 방금 생긴 글 클릭
  2. "(여기에 내 생각 한 줄)"을 지우고 진짜 내 생각 쓰기
맨 위 머리말이 표처럼 보여도 정상이에요. 그 부분은 건드리지 않아요. 저장 버튼 없이 자동 저장돼요.
한 걸음 더글쓰기를 두 번 더 해서 글 3개 만들기
STEP 4

내 블로그 금고 만들기

두 길이 있어요. A. 클로드에게 맡기기와 B. 내 손으로. 오늘 어느 길로 갈지는 수업에서 안내해요. 한 길이 막히면 다른 길로 가면 되고, 어느 길이든 STEP 5부터는 같아요.

4-0

클로드에게 금고 열쇠를 맡길 때

쉽게 말하면클로드가 금고에 글을 넣으려면 이 컴퓨터에서 깃허브에 한 번 로그인해야 해요. 열쇠를 잠깐 맡기는 거예요.

꼭 지킬 세 가지
  1. 비밀번호·토큰(깃허브 비밀 열쇠 글자)을 대화창에 붙여 넣지 않기 — 대화 기록에 남아요. 로그인은 브라우저 승인이나 짧은 코드로만.
  2. 로그인은 코드 탭에서만 — 채팅·코워크에서 토큰을 달라고 하면 거절하기.
  3. 끝나면 반드시 열쇠 돌려받기(STEP 7-1) — 공용 컴퓨터라 안 지우면 다음 사람이 내 금고에 넣을 수 있어요.
A-1

코드 탭 열기 A 길

  1. 클로드 앱 위쪽 코드 탭 → 새 작업창 열기
  2. 폴더 선택에서 blognote가 들어 있는 곳을 고르기 (USB 맨 위를 권해요)
왜 blognote 바깥을 고를까금고의 사본(my-blog 폴더)을 blognote 옆에 만들기 위해서예요. 공책과 금고 사본이 나란히 놓여요.

폴더 칩에 USB 이름이 보이면 성공

A-2

깃허브 로그인 (열쇠 맡기기) A 길

코드 탭에 붙여 넣기
[상황] 블로그 글을 깃허브에 올리려 한다. 여기는 여러 사람이 쓰는 공용 컴퓨터다.
[요청] 이 컴퓨터에서 내 깃허브 계정에 로그인할 수 있게 도와줘.
[조건] 비밀번호나 토큰을 대화창에 달라고 하지 마. 브라우저 승인이나 기기 코드 방식으로 해줘. 필요한 프로그램이 없으면 설치해도 되는지 먼저 물어봐.
  • 브라우저에 깃허브 승인 화면이 뜨면 → Authorize
  • 화면에 짧은 코드(예: ABCD-1234)가 뜨면 → 열린 깃허브 페이지에 코드 입력 → Continue → Authorize

클로드가 로그인됐다며 내 깃허브 아이디를 말하면 성공

토큰을 붙여 달라고 하면하지 말고 B 길로 가요.
A-3

금고(저장소) 자동으로 만들기 A 길

쉽게 말하면클로드가 내 블로그 틀을 직접 만들고, 내 글을 넣어서, 내 아이디에 금고를 만듭니다. 받을 파일도 적을 아이디도 없어요 — 로그인한 내 계정에 자동으로 생겨요.

코드 탭에 붙여 넣기
[요청] blognote 옆에 my-blog 폴더를 만들고, md 글을 블로그로 바꿔 주는 틀을 직접 만들어 줘.
- build.js: posts 폴더의 md 글(맨 위 --- 머리말의 title, date, tags, summary)을 읽어 public 폴더에 index.html과 글마다 html을 만들기. node만 쓰고 다른 설치는 하지 마.
- 최신 date가 맨 위, draft: true 글은 숨김, 글 페이지에는 "← 글 목록" 링크
- 디자인은 style.css 한 파일로 분리. 흰 바탕, 큰 글자, 휴대폰에서도 잘 보이게
- settings.md(blog_title, author, intro)를 읽어 제목과 소개 표시
- vercel.json: {"framework": null, "buildCommand": "node build.js", "outputDirectory": "public"} / package.json의 build는 node build.js / .gitignore에 public
- blognote/posts 안의 md 글을 my-blog/posts에 복사
다 만들면 node build.js로 미리보기를 만들어 public/index.html을 브라우저로 열어 줘.
잘 뜨면 지금 로그인한 내 깃허브 계정에 비공개(Private) 저장소 my-blog로 올려 줘.
[조건] blognote의 inbox 파일은 절대 올리지 마. 다 하면 저장소 주소와 올린 파일 목록을 보여 줘.
틀 만들다 막히면단톡방의 blog-template.zip을 blognote 옆에 두고 이 zip을 풀어서 my-blog로 쓰고 이어서 해줘

클로드가 github.com/내아이디/my-blog 주소와 올린 파일 목록을 보여 주면 성공

  • 그 주소를 열어 Private 표시와 posts 안의 내 글 확인
  • 블로그 이름 바꾸기: settings.md의 블로그 이름을 ○○○, 내 이름을 별명 ○○로 바꿔서 올려줘
"이미 my-blog가 있다"고 하면 → my-blog2로 만들어줘
A-4

올리기 전에 내 눈으로 미리보기 A 길

쉽게 말하면전광판에 걸기 전에 내 컴퓨터에서 먼저 봅니다. AI가 만든 건 사람이 확인하고 내보내요.

코드 탭에 붙여 넣기
my-blog 폴더에서 블로그 미리보기를 만들어 줘(node build.js). 다 되면 public/index.html을 브라우저로 열어 줘.

내 블로그가 브라우저에 뜨고, 글을 눌렀다가 "← 글 목록"으로 돌아올 수 있으면 성공

미리보기가 안 만들어지면이 컴퓨터에서 미리보기 프로그램이 안 도는 경우예요. 건너뛰고 STEP 5에서 전광판으로 바로 확인해요.
A-5

디자인이 별로면 바꾸기 선택

쉽게 말하면글(md)은 그대로 두고 옷(style.css)만 갈아입혀요.

코드 탭에 붙여 넣기 · [ ] 안은 하나 골라 바꾸기
my-blog의 style.css만 고쳐서 [따뜻한 카페 / 깔끔한 신문 / 파스텔 / 다크 모드] 느낌으로 바꿔 줘.
build.js, posts, settings.md는 건드리지 마. 바꾼 뒤 미리보기를 다시 만들어 브라우저로 열어 줘.
  • 마음에 들 때까지 "색을 더 진하게", "글자를 더 크게"처럼 말로 고치기
  • 마음에 들면 바꾼 style.css를 깃허브에 올려 줘
망가졌다면style.css를 처음 상태로 되돌려 줘 — 금고에 기록이 남아 있어서 되돌릴 수 있어요.
B

B. 내 손으로 하는 길 A가 막혔을 때

쉽게 말하면클로드 대신 내가 깃허브 웹사이트에서 직접 합니다. A를 끝낸 분은 STEP 5로 건너뛰세요.

B-1

틀로 내 금고 만들기 B 길

  1. 단톡방의 블로그 틀 주소 열기
  2. 오른쪽 위 초록 Use this template → Create a new repository
  3. Repository name: my-blog
  4. Choose visibility 버튼이 Public이에요 → 눌러서 Private
  5. 맨 아래 Create repository → "Generating..." 화면이 잠깐 떠요 (안 넘어가면 Refresh)
기본값이 Public꼭 Private으로 바꿔요.

왼쪽 위가 "내아이디 / my-blog"로 바뀌고 build.js, posts 등이 보이면 성공

B-2

블로그 이름 바꾸기 B 길

  1. 파일 목록에서 settings.md → 오른쪽 위 연필
  2. 세 줄만 고치기: blog_title: 블로그 이름 / author: 별명 / intro: 한 줄 소개
  3. Commit changes... → 창에서 한 번 더 Commit changes
지우면 안 되는 것blog_title: 같은 앞 글자와 맨 위아래 ---
Commit은 "저장하고 금고에 넣기"예요.
B-3

내 글 올리기 B 길

  1. 파일 목록에서 posts 폴더를 눌러 안으로 들어가기 (위쪽 경로가 my-blog / posts)
  2. 오른쪽 위 Add file → Upload files
  3. 내 컴퓨터 blognote/posts의 md 글을 끌어다 놓기 → Commit changes
올리는 건 posts의 내 글만inbox 파일은 기사 본문이 통째로 들어 있어서 절대 올리지 않아요.

posts 안에 "첫 글.md"와 내 글이 같이 보이면 성공

내 글이 posts 밖에 올라갔다면그 파일 → 연필 → 파일 이름 앞에 posts/를 붙여 Commit. 이름만 바꿔도 posts 안으로 옮겨져요.
STEP 5

전광판 켜기

버셀이 금고를 지켜보게 연결하면, 인터넷 주소가 생기고 블로그가 뜹니다.

5-1

금고와 전광판 연결하기

  1. 버셀 대시보드 오른쪽 위 + Create New → Project (또는 주소창에 vercel.com/new)
  2. 아래 왼쪽 Import Git Repository 목록에서 my-blog 옆 Import
  3. 설정 화면(Project Name, Application Preset: Other)은 아무것도 바꾸지 않고 Deploy

30초쯤 뒤 Congratulations! 화면과 내 블로그 그림이 뜨면 성공

목록에 my-blog가 없다면목록 아래 Adjust GitHub App Permissions → 새로 뜬 깃허브 창에서 Only select repositories → Select repositories에서 my-blog 검색해 클릭 → Save(처음이면 Install) → 버셀 화면 새로고침 → Import. 전부 말고 my-blog 하나만 허락하는 게 안전해요.
5-2

내 블로그 주소 받기

  1. 프로젝트 Overview → Domains에 보이는 가장 짧은 주소 복사
  2. 카톡 나에게 보내기 → 휴대폰으로 열어 보기

로그인 안 한 휴대폰에서 내 글 목록이 보이면 성공

주소 뒤에 영어 단어와 숫자가 자동으로 붙어요(예: my-blog-olive-omega-21.vercel.app). 사람마다 달라요.
블로그 주소는 누구나 볼 수 있어요금고는 비공개지만 블로그는 공개예요. 전화번호·주소 같은 개인정보는 올리지 않아요. 긴 주소는 미리보기용이라 남이 열면 로그인 화면이 뜰 수 있어요.
5-3

깃허브가 막혔다면 — 버셀로 바로 올리기 비상구

쉽게 말하면금고를 건너뛰고 전광판에 직접 붙여요.

  1. 단톡방의 blog-template.zip 받아서 압축 풀기
  2. 풀린 폴더의 posts에 내 md 글 넣기, settings.md를 메모장으로 열어 이름 세 줄 고치기 (내 이름은 별명으로)
  3. vercel.com/drop에 그 폴더를 통째로 끌어다 놓기 → 프로젝트 이름 my-blog → Deploy
"루트 페이지를 고르라"는 메뉴가 나오면멈추고, 클로드에게 압축 푼 블로그 틀 폴더에서 build.js를 실행해서 public 폴더를 만들어 줘 → 생긴 public 폴더만 끌어다 놓기
이 길의 차이글을 고치면 다시 끌어다 놓아야 해요. 대시보드의 그 프로젝트 위에 놓으면 주소는 그대로예요. 깃허브를 연결하면 이 과정이 자동이 돼요.
STEP 6

새 글을 넣으면 맨 위에 뜬다

오늘의 하이라이트. 기사 하나 긁고, 글 쓰고, 넣으면, 전광판이 알아서 바뀌는 걸 내 휴대폰으로 확인합니다.

6-1

한 바퀴 돌리기

  1. 기사 하나 더 웹 클리퍼로 긁기 (원하면 정리도)
  2. 「블로그 공책」에서 글쓰기
  3. 옵시디언에서 내 생각 한 줄
  4. 금고에 넣기
    • A 길: 코드 탭에 blognote/posts의 새 글을 my-blog/posts에 복사하고 미리보기 열어줘 → 확인 → 깃허브에 올려줘
    • B 길: 깃허브 my-blog → posts → Add file → Upload files → 새 글 → Commit
    • 버셀로 바로 올린 분(5-3): 압축 푼 폴더의 posts에 새 글 넣기 → 버셀 대시보드의 my-blog 프로젝트 위에 폴더를 다시 끌어다 놓기
  5. 30초~1분 기다리기 (버셀 대시보드에서 Building이 돌아가는 게 보여요)
  6. 휴대폰에서 내 블로그 새로고침

방금 쓴 글이 맨 위에 "최신" 표시로 뜨면 성공

지난주와 비교해 보세요바탕화면에 쌓아 두던 자료가, 오늘은 내 이름이 걸린 블로그 글이 됐어요.
6-2

글 고치기 선택 · 깃허브 길

  1. 깃허브 posts → 내 글 → 연필 → 한 글자 고치기 → Commit
  2. 1분 뒤 블로그 새로고침
고친 기록은 금고에 다 남아요. 파일 위 History에서 볼 수 있어요.
6-3

글 숨기기 선택 · 깃허브 길

글 맨 위 머리말에 draft: true 한 줄을 넣고 올리면 블로그에서 사라져요. 파일은 금고에 그대로 있어요.

STEP 7

열쇠 돌려받고 귀가

오늘 가장 중요한 카드가 여기 있어요. 공용 컴퓨터에 내 열쇠를 두고 가지 않습니다.

7-1

깃허브 열쇠 돌려받기 (로그아웃)

A 길(클로드에게 맡기기)로 한 분은 절대 빼먹지 않기안 하면 다음 반 사람이 내 금고에 글을 넣을 수 있어요. B 길로만 한 분은 3번부터 하면 돼요.
코드 탭에 붙여 넣기
이 컴퓨터에서 깃허브 로그아웃을 하고, 저장된 깃허브 로그인 정보(인증 정보)를 모두 지워 줘. 지워졌는지 확인해서 결과를 보여 줘.
  1. 클로드가 "로그인된 계정 없음"을 보여 주면 1차 성공
  2. 한 번 더: 윈도우 시작 → 자격 증명 관리자 → Windows 자격 증명 → github가 들어간 항목이 있으면 제거
  3. 크롬에서 깃허브·버셀 로그아웃 (구글로 가입한 분은 구글도)
  4. D: 드라이브에 만든 분은 blognote·my-blog 폴더를 USB로 복사한 뒤 D:에서 지우기
크롬이 "비밀번호를 저장할까요?" 물으면사용 안함. 실수로 저장했다면 크롬 설정 → 비밀번호 관리자에서 지워요.

자격 증명 관리자에 github 항목이 없으면 완료

USB의 my-blog 폴더는 그대로 가져가도 돼요. 열쇠는 그 안에 없어요.
7-2

귀가 체크

  • ☐ 7-1 깃허브 열쇠 돌려받기
  • ☐ 블로그 주소 카톡 나에게 보내기
  • ☐ USB 안전하게 제거
  • ☐ 클로드 로그아웃
  • ☐ 크롬에서 깃허브·버셀·구글 로그아웃
7-3

집에서 한 걸음 더 선택

도전방법
한 파일 블로그코드 탭에 my-blog에서 node build.js --single 실행해서 한 파일짜리 블로그 만들어줘 → blog-single.html 하나에 디자인과 내 그림까지 들어 있어 카톡·메일로 보내도 그대로 열려요. 그림은 base64(그림을 글자로 바꿔 파일 안에 넣는 방법)로 들어가요.
내 그림 넣기my-blog에 images 폴더를 만들어 그림을 넣고, 글에 ![설명](images/그림.png)
완전 자동옵시디언 플러그인 Obsidian Git을 집 컴퓨터에 깔면, 공책에 쓰기만 해도 몇 분마다 금고로 올라가요.
STEP 8

구글과 연결하기

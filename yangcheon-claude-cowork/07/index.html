오늘의 지도 — 한 마디로 블로그가 바뀐다

인터넷 기사를 모아 내 글로 쓰고, "올리기" 한 마디면 인터넷의 내 블로그 맨 위에 새 글이 뜹니다. 오늘은 그 길을 처음부터 끝까지 걸어 봅니다.

오늘 기억할 두 문장

둘출입증은 내가 끊고, 책은 클로드가 나른다. 로그인·권한 허락은 내가, 저장소 만들기·업로드·배포는 클로드가 해요.

STEP 1

원고 책상(폴더) 만들기

지난주 폴더는 그대로 두고, 오늘은 새 폴더로 처음부터 한 번 더 해요. 두 번 해 보면 집에서 혼자 할 수 있어요.

1-1

newsnote 폴더 만들기

  1. 바탕화면 빈 곳 마우스 오른쪽 → 새로 만들기 → 폴더
  2. 이름: newsnote (영어)
  3. 안으로 들어가서 폴더 두 개 더: inbox, posts

newsnote 안에 inbox, posts가 보이면 성공

폴더 위치를 꼭 기억하세요다운로드 폴더에 만들면 나중에 찾기 어려워요. 바탕화면을 권해요. 이름은 영어로(깃허브·버셀이 한글 이름을 싫어해요).
1-2

왜 폴더를 나눌까 — 출판사 이야기

  • inbox = 자료 상자: 인터넷에서 모은 기사 스크랩. 원본은 그대로 둬요.
  • sorted = 분야별 자료철: 클로드가 "AI 동향", "교육 동향"처럼 분야별로 나눠 꽂은 복사본
  • posts = 내 원고: 자료를 보고 쓴 내 블로그 글
자료 상자에 100개, 1,000개가 섞여 있으면 나도 클로드도 못 찾아요. 자료철이 나뉘어 있어야 "AI 동향 자료철에서 골라 글 써 줘"가 돼요.
STEP 2

옵시디언은 md 메모장, 웹 클리퍼는 기사를 자료 상자에 바로 넣어 주는 스크랩 가위예요. 이미 깔려 있으면 건너뛰어요.

# 뉴스 공책 규칙

## 내 정보
- 내 깃허브 저장소 이름: ________
- 블로그 폴더: newsnote 안의 site 폴더

## 폴더
- inbox/ : 웹클리퍼로 모은 기사 원본. 옮기거나 고치거나 지우지 않는다.
- sorted/<주제>/ : 주제별로 나눈 기사 복사본. 주제 폴더 이름은 짧은 한국어(예: AI 동향, 교육 동향).
- posts/ : 내가 쓰는 블로그 글.
- site/ : 깃허브에 올라가는 내 블로그 폴더(블로그 틀 + 올린 글).

## 정리
- "정리"라고 하면 inbox에 있는 기사 중 sorted에 아직 없는 것만 읽고, 알맞은 sorted/<주제>/에 복사한다. inbox 원본은 그대로 둔다.
- 주제 폴더는 3~6개로 유지한다. 비슷하면 합치고, 맞는 곳이 없으면 새로 만든다.
- 기준이 애매한 기사는 어디에 넣었는지와 이유를 한 줄로 알려 준다.

## 글쓰기
- "글쓰기"라고 하면 sorted의 기사 하나를 골라(내가 지정하면 그것) posts/에 블로그 글 md 한 편을 쓴다. 이미 글로 쓴 기사는 고르지 않는다.
- 맨 위 머리말은 반드시 이 모양으로 쓴다:
  ---
  title: 글 제목
  date: YYYY-MM-DD HH:mm   (지금 날짜와 시각)
  tags: [주제 폴더 이름]
  summary: 한 줄 소개
  source: 원문 주소
  ---
- 남의 기사 본문을 그대로 옮기지 않는다. 요약 + 내 생각 + 출처 링크. 사진은 넣지 않는다.
- 제목이나 요약에 콜론(:)이 있으면 큰따옴표로 감싼다.

## 올리기
- "올리기"라고 하면 posts/의 새 글을 site/posts/에 복사하고, 「내 정보」의 깃허브 저장소에 올린다.
- 올릴 때는 내장 브라우저로 github.com의 내 저장소를 열어, posts 폴더 안에서 웹 업로드(Add file → Upload files)로 새 글 파일만 넣고 Commit 한다. 이미 저장소에 있는 글은 다시 올리지 않는다.
- site/style.css나 site/settings.md가 바뀌었으면 그것도 저장소 맨 위에 올린다.
- 깃허브 로그인 화면이나 권한 허락 화면이 나오면 멈추고 나에게 직접 하라고 말한다. 비밀번호·토큰은 절대 받지 않는다.
- inbox, sorted, site/public은 올리지 않는다. 올린 뒤 저장소 주소와 올린 파일 이름을 보여 준다.

옵시디언 왼쪽에 CLAUDE 파일이 생기고, 눌러서 내용이 보이면 성공

💡 선생님이 리허설에서 한 실수 — 나는 피하기
  • 저장소를 내가 먼저 깃허브에서 만들어야 하나 헷갈렸어요 → 아니요. 이름만 CLAUDE.md에 적으면 클로드가 만들어요.
  • 글을 6편이나 한꺼번에 올려서 15분 걸렸어요 → 처음엔 1~2편만.
  • "코워크에서는 깃허브 로그인이 막혀 있다"는 말에 놀랐어요 → 정상이에요. 그래서 내장 브라우저로 해요.
  • "암호키를 열거하도록 허용?" 창 → 거부. 거부해도 로그인돼요.
6-1

블로그 틀 만들기

쉽게 말하면md 원고를 블로그 책 모양으로 찍어 내는 판형을 클로드가 만들어요. 클로드는 자기 작업 공간(클라우드)에서 만들고 결과만 내 폴더로 보내 줘요. 내 컴퓨터엔 아무것도 설치하지 않아요.

코워크에 붙여 넣기
[요청] newsnote 안에 site 폴더를 만들고, md 글을 블로그로 바꿔 주는 틀을 직접 만들어 줘.
- build.js: site/posts의 md 글(맨 위 --- 머리말의 title, date, tags, summary, source)을 읽어 site/public 폴더에 index.html과 글마다 html을 만든다. node만 쓰고 다른 설치는 하지 않는다.
- 글 목록은 date가 최신인 글이 맨 위. date는 "YYYY-MM-DD HH:mm"까지 읽어 날짜와 시각을 함께 보여 준다. draft: true 글은 숨긴다.
- 글 페이지에는 "← 글 목록" 링크와 원문 출처 링크.
- 디자인은 style.css 한 파일로 분리. 흰 바탕, 큰 글자, 휴대폰에서도 잘 보이게.
- settings.md(blog_title, author, intro)를 읽어 맨 위 제목과 소개에 보여 준다. 처음 값은 임시로 채워 둔다.
- vercel.json: {"framework": null, "buildCommand": "node build.js", "outputDirectory": "public"}
- package.json의 build는 node build.js / .gitignore에 public과 node_modules
- newsnote/posts의 md 글을 site/posts에 복사한다.

왜 이 버튼은 클로드가 안 눌러 줘요?

쉽게 말하면서점이 서고의 책을 가져가려면 출판사 주인인 내가 "이 서가는 가져가도 돼" 하고 출입증을 끊어 줘야 해요. 클로드는 책을 나르는 직원이라 출입증을 끊어 주는 버튼에서는 일부러 멈춰요. 고장이 아니라 안전장치예요.

인터넷의 나쁜 페이지가 클로드에게 "서고를 다 열어"라고 시킬 수도 있거든요. 그래서 출입증 버튼은 언제나 사람이 눌러요.
